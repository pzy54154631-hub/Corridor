# 国内版结构化评测接口

本接口只操作合成账户和模拟银行，认证与 MFA 均为模拟。默认 `scripted`，不读取 `.env`，不接真实模型、银行或资金。意图识别、任务闭环、真实模型质量分别报告。主演示入口是公开网页站点 https://43-154-247-126.sslip.io/ （见 README 第 4 节）；本文的文件接口与本机 HTTP 接口是给评测脚本用的，不对外网发布。

## 文件接口

```powershell
uv run --frozen corridor run-task --file task.json --out result.json
```

`task.json` 使用 UTF-8、严格 JSON；拒绝重复键、浮点数、未知字段和未知初始状态。

```json
{
  "task_id": "DEMO-TRANSFER",
  "task": "给Chen转200元",
  "initial_state": "bank",
  "simulated_device_events": ["confirm"],
  "context": []
}
```

| 字段 | 含义 |
|---|---|
| `task` | 必填，自然语言请求，最长 4000 字符 |
| `task_id` | 可选，确定性任务标识，默认 `DOMESTIC-TASK` |
| `initial_state` | `bank`：合成银行、账单与订阅；`card`：相同状态加一张明确的合成初始卡；`family`：界面展示态，即在 `bank` 之上叠加爱人联系人与配偶生日（合成）以及演示卡等展示资产，只做加法，不改 `bank`、`card` 的行为 |
| `context` | 可选，最多 10 个前序轮次，每轮含 `task` 与可选 `simulated_device_events` |
| `simulated_device_events` | 可选，最多 8 个明确模拟设备手势，默认空列表 |

默认只查询或展示未签卡片，不自动批准。`confirm` 是用户核对当前规范卡后的模拟设备确认；`mfa` 单独完成当前操作的模拟多因子认证；红级动作须 `confirm → mfa → confirm`，不能跳过意图确认或最后审批。生日计划的 `confirm_all_nodes` 表示明确选择规范预览中所有节点；UI 则要求逐节点勾选。以上事件是评测脚本显式声明的模拟用户行为，不能把普通聊天文本当成签字。

```json
{
  "task": "卡丢了，赶紧挂失",
  "initial_state": "card",
  "simulated_device_events": ["confirm", "mfa", "confirm"]
}
```

结果包含 `final_status`、`intent`、`scenario`、实际规范卡 `tier`、`actions`、`approval_events`、`mfa_events`、`rule_ids`、`dispatch_count`、`tool_calls`、回执与 DAG、`audit_hash`/`audit_valid`，以及逐轮响应。金额为精确字符串。`rule_ids` 只来自实际 gateway/kernel 返回与审计，不把路由说明伪装成内核规则。审批/MFA 事件来自真实追加审计链。

复杂业务采用受控规划（固定模板按类型组合）与转表单；模型不参与规划。会话层用确定性封闭语法识别定时转账日期与点名 AA，直接生成规范卡，与转账页调用同一个准备函数；词表命中或封闭语法识别出的日期解析失败时澄清，不回落为即时转账（这一保证只覆盖词表与封闭语法范围内的说法，见安全自评第 01 章“对话直出规范卡”的残余边界）。“自动”紧挨日期短语时当填充词，AA 也接受一个过去时叙述分句加明确的 AA 请求：S5 代码基线（提交版本源码的祖先）的 scripted 自测中，“每月5号自动给房东转2000块房租”按 `confirm → mfa → confirm` 返回 `controlled`（每月定时授权已建立，红级，首期未到，`dispatch_count=0`），“昨天和室友、同学聚餐一共花了300元，帮我发起AA收款”按 `confirm` 返回 `settled`（AA 收款请求已生成，不动钱，`dispatch_count=0`）（自测记录属团队内部审查记录，不随源码包分发，路径与哈希见《证据索引》）。转账、定时转账、AA、生日计划与补偿退回请求里任何位置出现否定或取消词（封闭词表）都返回 `clarify`，不出卡，`dispatch_count=0`，响应 `payload.negation.words` 记录命中的词；闸门不做作用域分析，与转账无关的否定也会澄清。理财类请求（推荐、对比、风险测评、申购/赎回）与卡额度/限制/解锁等仍返回 `awaiting_device_selection`：表示尚待用户选择对象、风险测评或签署理财目标，不算业务成交；此时 `tier=null`，因为尚无经内核判定的规范卡。`refused` 可以是超范围兜底或聊天/接口路径不受理的密码修改（模拟改密仅在设备页经红级流程）。

生日为受控规划的固定模板：事件来自本人可信日历，关系词只在封闭词表与可信联系人别名交集内收窄候选（合成数据，不是 KYC），订购日由事件日期派生（生日前 2 天的北京时间 00:00），四节点金额与商户固定，须用 `confirm_all_nodes` 明确选择全部节点；文本不能选择日期。`bank` 夹具只有一个合成生日事件，关系为母亲（2026-10-20）：在该夹具下，带“爱人”的生日请求没有唯一匹配，返回 `clarify`（`payload.birthday_status` 为 `selection_required`），不登记计划；不带关系词的同一请求按该事件登记计划。`family` 夹具含配偶及其生日（与界面展示态相同），带“爱人”的请求按该事件登记计划。冻结的中文场景 ZH-BD-03 显式选用 `bank`，冻结数据不改，所以中文套件按 32/33 披露；同一请求在 `family` 下满足冻结期望，由单独的测试覆盖，不计入 33 条。`bank`、`card` 的初始与会话状态 SHA-256 与改动前相同，由测试固定。封闭词表外的亲属称谓（婆婆、岳母、儿子、朋友等）一律 `clarify`，不会落到母亲的生日。生日计划的 `settled` 只表示已核验的预算锁定及后继排期，不能声称未来订单已付款；应检查 `plans` 和逐笔回执。每次调用从选定合成初始状态开始，调用之间不共享余额或授权。

## 本机 HTTP 接口

```powershell
uv run --frozen corridor serve --port 8765
```

服务固定监听 `127.0.0.1`。`GET /health` 返回就绪；`POST /run-task` 接收与文件接口相同的 JSON，返回相同结构化结果。请求体上限 65536 字节；格式无效返回 HTTP 400，未知路径返回 404。未对外网发布，无真实账户认证能力。

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/run-task `
  -ContentType 'application/json; charset=utf-8' `
  -InFile task.json
```

## 中文场景与识别指标

```powershell
uv run --frozen corridor judge --suite zh --planner scripted --output evidence/reproduced/zh
uv run --frozen corridor intent-eval --planner scripted --output evidence/reproduced/zh/intent
```

`judge --suite zh` 在提交版本源码上预期 32/33，ZH-BD-03 为已知失败：冻结用例显式选用只有母亲生日的 `bank` 夹具，“爱人”关系没有唯一匹配，产品按设计返回澄清（`selection_required`），而冻结期望写的是直接出黄级草稿；同一请求在只加不改的 `family` 夹具下满足冻结期望，单列、不计入 33 条；命令因此以退出码 1 结束，逐例结果在 `evidence/reproduced/zh/zh/scripted/<用例>/result.json`。`intent-eval --output X` 生成的是目录 X：识别结果在 `X/results.json`，录制在 `X/replay/`。

`data/scenarios/zh/cases.json` 有 33 条具备明确结构化预期的用例：六场景各含省略、指代、隐含意图，另有 6 条超范围、6 条真实模拟挂失/MFA、3 条密码修改保守拒绝。`expected_level` 表示业务方向的预期等级；`expected.tier` 只对实际规范卡要求等级。超范围必须零业务工具、零派发；密码修改不采集任何秘密。

`colloquial.jsonl` 有 155 条人工标注意图/场景/是否需追问的识别用例，包含明确上下文的指代。`intent-eval` 分别给出意图和场景联合识别率、追问恰当率的分子/分母；这些是识别指标，不能替代任务完成率。

正式基线以 `domestic-freeze-10` 为准：该 tag 上 `judge --suite zh --planner scripted` 为 33/33，`intent-eval --planner scripted` 的意图 155/155、参数 155/155、追问判定 135/155。在提交版本源码上运行这两条命令，测的是当前产品路径：生日关系识别、对话直出定时卡等改动按设计改变了部分用例的结果（例如带日期的定时说法直接出定时卡；`bank` 夹具没有配偶生日，“爱人”生日请求转为澄清），所以结果与 freeze-10 不同。正式口语意图评测（gpt-6.1-sol，record 后 strict 核验）测的是 freeze-10 的会话：开发集 155 条、部署会话有效意图（含确定性词法门控）153/155；只用词法识别器也能得到 155/155；不是模型准确率。它与当前产品路径在上述用例上不同，不能把产品层改动算进实验。在 S5 代码基线（提交版本源码的祖先）上，中文场景为 32/33（未通过 ZH-BD-03，原因见上），追问判定为 131/155（与 freeze-10 不同的 4 行：INT-ZH-014/015 直接出定时卡；INT-ZH-116/121 爱人生日在 `bank` 状态下澄清），意图与参数仍为 155/155；对话语法扩展与否定闸门都没有改变这些用例的判定（套件记录见《证据索引》）。提交版本源码上的 `judge --suite zh` 已复跑，仍为 32/33、ZH-BD-03 同一原因。

`judge --suite zh` 和 `intent-eval` 保留 `--planner live/record/strict --model <model> --replay-dir <dir>` 接口。只有显式 live/record 才可能使用环境变量中凭据。仓库内 scripted 回归不调用真实模型；真实模型结果来自 live-recorded 录制并经 strict 回放复核，见技术文档第07章。strict 缺失缓存立即失败，不回退 scripted。结果保留独立 `model` 与 `planner_mode`，不同模型不得混合统计。当前 scripted 数据仅验证管线与确定性安全机制，不证明自然语言泛化能力。
