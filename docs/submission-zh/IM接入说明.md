# IM 接入说明（模拟渠道）

`src/corridor/channels/im.py` 是同一 `DomesticSession` 会话 API 的纯文本适配器。Streamlit 本地备用入口的「IM 视图」用于演示消息进、规范卡文本及按钮出的交互；网页主入口（公开站点）没有 IM 视图；没有连接企业微信、飞书或其他真实机器人。

```python
from corridor.agent.domestic_session import DomesticSession
from corridor.channels.im import IMAdapter

# controller 已由明确的模拟设备登录动作启动；与 APP 共用同一个实例。
channel = IMAdapter(DomesticSession(controller))
message = channel.receive("给Chen转200元", request_id="message-001")
# 展示 message["text"] 与 message["buttons"]，此时资金尚未派发。
result = channel.click("confirm", message["response_id"])
```

消息包含稳定 `response_id`、结构化状态、规范卡、真实规则命中、审计哈希和按钮。相同 `request_id` 不能替换原消息；每个按钮绑定其展示过的 `response_id`。重发已完成确认复用结果，不重复付款。文本中写「已确认」不能替代按钮；按钮点击才是独立的模拟设备手势。

红级动作必须先确认意图，再通过 `verify_mfa`，最后再次 `confirm`。生日计划为受控规划的固定模板：事件来自本人可信日历，订购日由事件日期派生，锁款、解锁、鲜花、蛋糕四节点的金额与商户固定；必须把用户逐节点明确勾选的 `selected_node_ids` 传给确认，适配器不替用户选节点，文本也不能选日期。复杂业务采用受控规划（固定模板按类型组合）与转表单：定时转账与点名 AA 与 APP 走同一会话路径，返回规范卡文本和按钮；“我们N个AA”需要补选参与人时，IM 只显示文字提示，补选只在 APP 对话页提供；申购、赎回与取消订阅要素齐全时在对话中核对或出卡，理财推荐、对比与风险测评及卡额度、限制与解冻仍待设备选择，待设备选择不代表完成。停止会撤回未执行提案，旧按钮不能重新取得权限。绿色查询可直接使用已有只读会话授权。所有业务调用仍经既有 controller、gateway、dispatch 重检和审计链。

否定 / 取消闸门在会话层，IM 与 APP 相同：转账、定时转账、AA、生日计划与补偿退回请求里带否定或取消词时不出卡，IM 回复“这句话里有否定或取消的说法……没有生成新的卡片；本条消息没有执行任何操作”，请用户去掉否定后重说，或说“停止”中断计划、撤回待确认的卡片。

IM 纯文本渠道与 APP 共用会话与裁决，但没有 APP 规范卡旁的防骗提醒（未实现），也没有向新收款人付款前的“请您核实收款人”问答（IM 模拟页经 APP 对话组件显示的问答除外），没有“附上外部文件”入口及对应提醒，也没有客户视图的白话文案；对话里的流水查询在 IM 只回通用文字，表格与 AA 补参卡只在 APP 对话页显示。这些是已知的展示层差距，不影响裁决。

未来对接企业微信/飞书机器人时，外层接入服务负责验证平台回调签名、去重平台消息 ID、把已认证主体映射到独立会话，并把本文的文本/按钮结构转换为平台卡片。平台回调签名不等于银行设备授权；红级 MFA 和规范卡确认应跳转到独立设备渠道，不能在群聊内传密码、OTP、银行卡号或审批 token。接入服务只能调用会话 API，不能直接调用 MockBank 或生成内核金额。

当前适配器不实现真实平台鉴权、平台 API 调用或生产 MFA，所有界面及输出常驻「模拟 IM · 合成数据 · 模拟认证」。这份说明是接口接入设计，不能当成已完成真实 IM 联调的证据。
